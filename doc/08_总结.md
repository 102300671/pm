# 08. 总结

## 7.1 工作回顾

本次《软件工程》综合实验围绕选题 14「患者监护系统」，完整经历了软件工程的六个阶段：

| 阶段 | 主要工作 | 产出 |
|------|----------|------|
| 可行性研究 | 技术/经济/操作三维分析 | 可行性研究报告 |
| 需求分析 | 数据流图、数据字典、功能分解 | 软件需求规格说明书 |
| 总体设计 | 分层架构、模块划分、调用关系 | 总体设计说明书 |
| 数据库设计 | ER 图、四表详细设计、索引优化 | 数据库设计说明书 |
| 详细设计 | 核心模块流程图、盒图、接口定义 | 详细设计说明书 |
| 编码实现 | Python + SQLite + tkinter | 9 个源文件，约 800 行 |
| 测试 | 17 项自动化测试 + 10 项手动 GUI 测试 | 测试分析报告 |

## 7.2 技术收获

1. **从零搭建可运行系统**：从空目录到完整 GUI 应用，串联了数据库设计、业务逻辑、界面开发全链路
2. **分层架构实践**：DAO → Service → GUI 三层解耦，修改数据层不影响业务层
3. **Mermaid 文档可视化**：所有图表（DFD、ER、流程图、软件结构图）用 Mermaid 在 Markdown 中直接绘制
4. **threading 多线程**：定时采集线程与 GUI 主线程通过 `root.after()` 安全通信

## 7.3 遇到的问题

| 问题 | 解决方案 |
|------|----------|
| 随机信号全部都在安全范围内，看不到报警效果 | 调整模拟算法，让体温有 10% 概率冲高、心率有 5% 概率过低 |
| 同一指标持续超限导致报警刷屏 | 引入 `pending` 状态去重，同一病人同一指标只保留一条待处理报警 |
| tkinter 跨线程安全 | 监控线程直接调用 GUI 组件会崩溃，改用 `root.after(0, callback)` 调度到主线程 |
| SQL distinct on 在 SQLite 不支持 | 用子查询 `MAX(record_time)` 模拟 postgres 的 `DISTINCT ON` |

## 7.4 系统不足与改进方向

| 不足 | 改进方向 |
|------|----------|
| 生理信号随机模拟，无真实传感器接入 | 定义 `SignalProvider` 接口，可实现真实设备驱动 |
| 无用户登录/权限控制 | 增加用户表 + 登录模块 |
| 报告仅支持纯文本 | 增加 HTML/PDF 导出 |
| 单机运行 | 可考虑 B/S 架构升级（Flask + Vue） |
| 报警无声音提示 | 增加系统提示音调用 |
