# 可行性研究报告

## 一、项目背景

目前住院病人主要由护士人工护理，这种方式存在两个突出问题：
1. **人力资源紧张**：需要大量护士轮班值守，护理成本高
2. **响应不及时**：护士不可能时刻盯着每位危重病人，可能延误抢救时机

某医院拟开发一个以计算机为中心的**患者监护系统**（Patient Monitoring System），通过自动化手段弥补人工监护的不足。

## 二、项目目标

| 目标 | 描述 |
|------|------|
| 实时监测 | 随时接收每位病人的生理信号（脉搏、体温、血压、心电图等） |
| 自动记录 | 定时记录病人情况，形成患者日志 |
| 智能报警 | 当生理信号超出安全范围时，自动向值班护士发出警告 |
| 报告生成 | 护士可按需查询并打印指定病人的病情报告 |

## 三、可行性分析

### 3.1 技术可行性 ✅

| 技术点 | 方案 | 说明 |
|--------|------|------|
| 开发语言 | Python 3 | 语法简洁，库生态丰富，适合快速开发 |
| 数据库 | SQLite 3 | 轻量级嵌入式数据库，无需单独安装服务，单文件管理 |
| GUI 框架 | tkinter | Python 标准库自带，零依赖，跨平台 |
| 数据模拟 | random 模块 | 用随机数模拟生理信号采集，代替真实传感器 |
| 定时任务 | threading.Timer | Python 标准库，可实现周期性记录 |

所需技术栈全部为开源免费、成熟稳定的技术，开发团队（课程学生）经过 Python 基础学习即可掌握，**技术风险极低**。

### 3.2 经济可行性 ✅

| 项目 | 说明 |
|------|------|
| 硬件成本 | 普通 PC 即可运行，无需专用设备 |
| 软件成本 | Python、SQLite、tkinter 均为免费开源 |
| 开发人力 | 单人 16 学时可完成 |
| 运行维护 | 零额外费用 |

**经济成本为零**，完全可行。

### 3.3 操作可行性 ✅

| 方面 | 说明 |
|------|------|
| 用户群体 | 值班护士、医生 |
| 界面风格 | 图形化界面，菜单驱动 |
| 学习成本 | 低，类似常规桌面软件操作 |
| 输出方式 | 屏幕显示 + 可打印报告 |

操作界面直观清晰，医护人员经过简单培训即可使用。

### 3.4 可行性结论

> **本项目在技术、经济、操作三个维度均完全可行，建议立即启动开发。**
